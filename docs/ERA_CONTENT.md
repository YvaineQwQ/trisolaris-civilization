## 2. 资源解锁与初始库存

| 资源 | 解锁时代 | 获取方式 | normal 初始库存 |
| --- | --- | --- | --- |
| `food` 食物 | 第 1 时代 | 农业 / 采集 | 900 |
| `water` 水 | 第 1 时代 | 取水 / 水利 | 500 |
| `energy` 能源 | 第 3 时代 | 发电（E3 解锁） | 0 |
| `minerals` 矿物 | 第 1 时代 | 采石 / 采矿 | 130 |
| `metals` 金属 | 第 2 时代 | 金属冶炼（E2 解锁） | 0 |
| `science` 科研点 | 第 1 时代 | 知识积累 | 10 |

- 食物 / 能源 / 科研的初始值来自难度预设（DIFFICULTIES.normal），其余来自 BASE_RESOURCE_STOCK；metals / energy 在未解锁时代被 game 层强制归零。
- E1：仅 food / water / minerals / science；**E1 建筑的成本与维护禁止 metals / energy**。
- E2：解锁 metals（青铜 / 铁），**仍无 energy（电力）**；水车、畜力以“动力”为名也不消耗 energy。
- E3：解锁 energy（电力），此后全部资源可用。
- 经济层 `TurnContext.era` 语义：`era < 2` 金属生产/需求置 0；`era < 3` 能源生产/需求置 0（无电力时代 `powerEfficiency = 1`）。不传 `era` 时保持旧行为（全资源解锁）。
- 观测任务在 `era < 3` 时以食物支付，`era >= 3` 时以能源支付（`game.ts startObservation`）。

## 4. 升级链全表

旧时代建筑在新一代文明中按 `outdatedMultiplier` 折减：当前时代 ×1、落后 1 代 ×0.8、落后 ≥2 代 ×0.6。
折减作用于**全部效果**（产出 / 住房 / 仓储 / 科研 / 观测 / 稳定度 / 隔热等）；维护与工人不折减，
因此“只造不升级”是双重惩罚。升级成本按目标建筑新建成本的约 6 折设定（本节末尾给出实测比例）。

## 10. 已知遗留与注意事项

1. **观星台 Lv.1 的 `upgradeCost` 为占位值**（含 energy 120）：Lv.1 由建造「观星台」建筑直接获得，
   `game.ts upgradeObservatory` 在 `level <= 0` 时直接拒绝并提示建造观星台，因此该成本不参与付费路径；
   内容自检测试对 Lv.2~Lv.6 做「成本资源 = 该级 requiresEra 已解锁资源」校验，Lv.1 显式跳过。
2. **升级链末端建筑仍保留 `upgradeCost` 字段**（如 `ecodomeCity`、`warehouse`、`deepSpaceArray`）：
   `upgradeTo = null` 时该字段不参与升级，保留仅为未来扩展；内容自检只要求「有前置的升级目标」必须有非空 `upgradeCost`。
3. **`ERAS[1].unlockSummary` 文案提到「冶坊」**，实现中 E2 的金属由「矿场」产出、E3 由「钢铁厂」产出；
   这是 `src/core/constants.ts` 的文案与实现的细微差异（不影响机制与测试），留待 lead 统一文案。
4. **观测升级的执行层在 `game.ts`**：systems 层负责条件与资源校验（`observation/observatory.ts checkUpgrade`），
   实际扣费与 `observation.level` 变更由 `game.ts upgradeObservatory` 完成；`tests/game` 覆盖执行路径，
   `tests/systems` 覆盖「E2 资源可行性 + 观测 Lv.2 满足 E3 条件」的可达性回归。
5. **数值为「定义表原始值」**：实际结算还要乘人力充足率（`staffingRatio`）、科技乘数、环境系数、
   时代效率修正（E2 +5% 科研、E3 +5% 建筑/+10% 科研……），因此实测净额与表中单栋数值不会简单相加。
